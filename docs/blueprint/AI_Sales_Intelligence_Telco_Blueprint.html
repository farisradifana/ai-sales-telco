1. Ringkasan

AI Sales Intelligence Telco adalah asisten penjualan untuk tim distribusi produk telekomunikasi (perdana, voucher, saldo) di Jawa Timur. Sales dan manajer cukup chat di WhatsApp: mencatat sell-in ke outlet, melihat stok, target, achievement, peringkat outlet/kecamatan/kabupaten, atau bertanya bebas ("kenapa sell-out Kebonsari turun?") yang dijawab AI dengan angka yang diverifikasi terhadap database.

AspekRingkasan
MasalahData penjualan tersebar; manajer lapangan butuh angka cepat di HP tanpa membuka dashboard; jawaban AI generik rawan mengarang angka.
SolusiSatu sumber kebenaran di PostgreSQL + perintah cepat tanpa AI + AI Agent ber-tool yang angkanya wajib berasal dari tool dan diverifikasi.
Pengguna938 posisi organisasi: 1 Head of Region, 2 Head of Sales (East/West), 38 Head of Branch, 231 Territory Manager, 666 Sales.
Data500.000 transaksi sintetis (100.000 sell-in + 400.000 sell-out) 1 Jan 2025 – 30 Sep 2026, seed 42, deterministik.
KeamananDefault-deny per wilayah, role database least-privilege, nomor WA terenkripsi, tiket AI satu giliran, ledger immutable.
Hasil125 tes otomatis lulus, CI hijau, uji live WhatsApp end-to-end, laporan < 1 detik, jawaban AI terverifikasi 14–26 detik.

3. Database

Satu database PostgreSQL 17 dengan tiga schema. Migrasi berurutan, immutable, dengan checksum; runner mengambil advisory lock sebelum tabel bookkeeping sehingga aman dijalankan bersamaan.

agent_memoryRiwayat chat AI Agent (6 pesan terakhir per akun, dihapus > 7 hari)Hanya role memory n8n; API hanya boleh menghapus

Jaminan integritas

  • Ledger dan event immutable: trigger reject_mutation menolak UPDATE/DELETE; koreksi lewat reversal/correction yang diaudit.
  • Stok tidak pernah negatif: CHECK quantity >= 0, kunci akun stok dalam satu transaksi, uji oversell konkuren dua koneksi.
  • Idempotensi posting: posting_request (hash payload) — replay mengembalikan hasil lama, isi berbeda → 409.
  • Backdate dibatasi watermark + masa tenggang; waktu posting diambil dari jam DB setelah lock.
  • Uang sebagai NUMERIC/Decimal (tidak pernah float); sell-in dan sell-out tidak pernah dijumlah; PCS dan saldo IDR dipisah.
  • Setiap angka yang ditampilkan berasal dari evidence_snapshot (immutable, ber-digest) milik principal yang meminta.
  • validate.sql + validate_platform.sql: audit relasi, kunci, stok kronologis, leg transfer, posting tanpa transaksi, dll.

4.4 Identitas layanan

  • n8n → API: Bearer N8N_SERVICE_TOKEN; API → n8n: header dispatch + tanda tangan HMAC.
  • AI tools: service token + tiket satu giliran di header X-Agent-Ticket (model tidak pernah melihat tiket).
  • Rekap Google Sheet: principal svc-recap (JWT 30 hari) + OAuth2 Google milik pemilik sheet.
  • Principal tidak pernah dikirim di body request; selalu diturunkan server dari token/identitas terverifikasi.

6. Langkah build (dari nol)

  1. Siapkan PostgreSQL 17 dan secret lokal (scripts/dev_secrets.py → .local/dev.env, tidak masuk git).
  2. Ambil data wilayah Jawa Timur (scripts/extract_jatim.py) lalu generate dataset: python -m telco.generate --out data/full --seed 42.
  3. Validasi CSV independen: python -m telco.validate_csv data/full (72 cek).
  4. Buat database, jalankan migrasi dua kali (idempoten), load 500k baris, validate; load kedua harus ditolak.
  5. Terapkan sql/security.sql + sql/security_platform.sql, lalu python -m telco_api.provision roles dan demo (principal & grant dari hierarki).
  6. Jalankan tes: pytest (clone disposable dari template) → 125 lulus.
  7. Setup WhatsApp Cloud API: app Meta, nomor bisnis, token, verify token, subscribe WABA; daftarkan penerima uji (terenkripsi + allowlist).
  8. Buat combo di 9Router (ai-sales + ai-sales-backup) dengan provider berizin ber-API key.
  9. Generate workflow n8n, buat credential (service token, dispatch header, recap JWT, Google Sheets OAuth2, 9Router, memory Postgres), import & publish.
  10. Siapkan domain di Cloudflare, buat named tunnel telco-wa → edge :8089, set Callback URL di Meta sekali.
  11. Pasang autostart: salin telco-startup.vbs ke folder Startup; watchdog menyalakan ulang layanan yang mati.
  12. Uji end-to-end dari HP: Halo → Menu → laporan → input sell-in → YA → cek Google Sheet.

7. Alur

7.1 Pesan masuk (semua jenis)

  1. Meta mengirim webhook → tunnel → edge → API memverifikasi tanda tangan HMAC raw body.
  2. Nomor pengirim di-hash (blind index) → dicocokkan ke principal; nomor asli tidak pernah disimpan polos.
  3. inbound_event disimpan (dedup per message_id; isi berbeda dengan id sama → 409); pengirim tak terdaftar tidak dibalas.
  4. Outbox mengirim dispatch ke n8n; n8n klaim event (lease) lalu API mengenali niat.
  5. Router: perintah cepat → lane 01b; input sell-in / YA / BATAL → lane 02; selain itu → AI Agent (lane 03).

7.2 Perintah cepat

  1. API menjalankan laporan deterministik dalam cakupan grant principal (default-deny) dan menyimpan evidence.
  2. Teks disusun untuk layar HP; balasan + tombol "Pilih Perintah" masuk outbox (reply_to = nomor pengirim).
  3. Lane outbox mengirim via WhatsApp Cloud API; mode live hanya ke nomor di allowlist.

7.3 Input sell-in

  1. "OUT-0061 SIM-NOVA-18 2, VCR-NOVA-3 10" → draft (cek outlet dalam cakupan, harga dari price_policy, stok cukup).
  2. Ringkasan + "Balas *YA kode* / *BATAL kode*", berlaku 30 menit.
  3. YA → posting atomik: kunci akun stok, ledger dua sisi, idempotensi; balasan "Tercatat" dengan total rupiah.
  4. n8n menambahkan baris ke tab Rekap dan satu baris log ke tab Info (gagal sheet tidak menghambat balasan).

7.4 AI Agent

  1. Agent start: cek & potong kuota harian per jabatan (advisory lock), buat tiket satu giliran (TTL 3 menit, maks 8 panggilan), system prompt sesuai jabatan.
  2. AI Agent n8n: model combo ai-sales (cadangan ai-sales-backup bila gagal), memory 6 pesan, tool HTTP dengan tiket di header.
  3. Setiap tool dicek ulang oleh API terhadap principal pemilik tiket dan disimpan sebagai evidence giliran itu.
  4. Agent finish: hapus ID teknis, ubah Markdown ke format WhatsApp, verifikasi setiap angka terhadap evidence giliran ini.
  5. Lolos → kirim jawaban (+ tautan grafik sell-out & sell-in bertanda tangan untuk diagnosis). Gagal → laporan baku dari evidence; tanpa tool → permintaan maaf + kuota dikembalikan.

7.5 Outbox & pengiriman

  • Klaim SKIP LOCKED + lease, kirim tanpa transaksi terbuka, ack/fail; retry bertahap dengan jitter, dead-letter.
  • Status Meta (sent/delivered/read) direkonsiliasi lewat biz_opaque_callback_data.
  • Pesan lanjutan (Pilih Perintah) ditahan sampai pesan induknya terkirim.

8. Keamanan & tata kelola

  • Otorisasi default-deny di SQL (can_access / can_access_area); data di luar cakupan tidak pernah keluar dari database.
  • Tidak ada permukaan SQL bebas; teks pengguna tidak pernah menjadi query; injeksi di nama outlet/pesan inert.
  • Model AI tidak bisa menulis transaksi; tool read-only; tiket terikat principal, allowlist tool, batas panggilan, TTL.
  • Verifikator angka menolak angka yang tidak ada di evidence giliran itu (termasuk angka dari memory chat).
  • Nomor WhatsApp: AES-256-GCM + HMAC; log hanya berisi ID korelasi; allowlist untuk mode live.
  • Secret di .local/ (gitignored) dan secret manager; tidak ada secret di repo, workflow, atau dokumen.
  • Retensi: memory AI 7 hari, eksekusi n8n 24 jam, tautan grafik bertanda tangan berumur pendek.
  • Kebijakan privasi: docs/PRIVACY.md (kontak resmi tercantum).

Bug nyata yang ditemukan & diperbaiki saat pengujian

  • Race migrasi pertama kali → advisory lock sebelum tabel bookkeeping.
  • Waktu posting diambil sebelum lock → transaksi bersamaan dianggap backdate → jam DB setelah lock.
  • Balasan dikirim ke nomor terbaru akun (nomor demo) → balasan kini ke nomor pengirim.
  • "Bulan lalu" dibandingkan dengan Juni (aturan periode sama panjang) → tool laporan bulanan untuk AI.
  • AI menyalin angka dari memory → aturan wajib tool per giliran + verifikator menolak.
  • Pesan menu bisa mendahului laporan saat retry → outbox menahan pesan lanjutan.

10. Batasan & langkah berikutnya

  • Saat ini berjalan di PC pemilik (autostart + watchdog); untuk produksi: deploy compose staging ke cloud dengan PostgreSQL terkelola, Redis + n8n queue mode.
  • Data organisasi, outlet, dan transaksi sintetis; wilayah riil Jawa Timur.
  • Pengingat target harian butuh template WhatsApp Utility yang disetujui Meta.
  • Login dashboard produksi perlu IdP perusahaan (JWKS).
